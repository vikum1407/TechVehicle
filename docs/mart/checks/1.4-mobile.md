# Milestone 1, Step 1.4 (mobile) — Detail screen — verification

Date: 2026-10-10. No temp script — pure UI/data-wiring code, verified by code read-through
against `04-screens.md` §3 and `npx tsc --noEmit`.

## What was built
- `mobile/src/screens/mart/DetailScreen.tsx` — header (back, Share, Favorite, Report —
  the last two hidden for the owner's own ad per spec), swipeable photo carousel (dots,
  status pill, grayed photos when sold, tap opens the existing `MartPhotoViewer`), info
  block (condition tag, price, title, location + `timeAgo`, delivery line, vehicle
  chips), description, seller row (avatar initials, name, Shop tag, `RatingBadge`,
  active-ads count), a horizontal "Similar Parts" strip (reusing `MartListingCard` inside
  a fixed-width wrapper rather than a new component), and the sticky bottom bar that
  switches between "Message Seller" (buyer), "Edit"/"Mark Sold" (owner), and a disabled
  "This item was sold" bar — matching all 4 states in §3's "States" section. Loading,
  network-error and not-found (404) states each render their own full-screen view before
  the rest of the screen even tries to read `detail`.
- `mobile/src/config/api.ts` — `getMartListingDetail()`, `getMartSimilarListings()`.
- `mobile/src/screens/MartNavigator.tsx` — added a real `'detail'` stack entry carrying
  `listingId`. Tapping a card on Mart Home, tapping a Similar Parts card on Detail
  (stacks another Detail rather than replacing it, so Back steps back through the chain
  correctly), and a successful Post Ad all now go to a real Detail screen — the last of
  these replaces the `postAd` stack entry with `detail` instead of pushing on top of it,
  so Back from the new ad's Detail goes to Home, not back into the submitted form.
- `mobile/src/screens/mart/MartHomeScreen.tsx` — card tap now calls the new
  `onOpenListing` prop instead of a stub alert.

## Decisions (logged in full in `DECISIONS-MADE.md`)
- Share/Favorite/Report/Message Seller/Edit/Mark Sold/seller-row-tap are a mix of "really
  works" (Share — native `Share.share`, no backend needed) and "Coming soon" stub
  (everything else, since Chat/Edit/Mark Sold/Report/Seller-profile don't exist until
  Steps 1.5/1.8/2.7/3.1) — same honesty rule as Mart Home and Post Ad: no faked
  persistence, no silently-broken buttons.
- The Similar Parts strip reuses `MartListingCard` wrapped in a fixed-width `View`
  (128px) rather than building a dedicated smaller card component — the existing card's
  internal `flex: 1` already fills whatever width its parent gives it.

## Verified by hand (code read-through + `tsc`)
- All 4 Detail states from §3 render distinctly: sold (grayed photos, gray pill, no
  Message button, disabled bar instead), reserved (amber pill, Message button still
  shown), own ad (Edit/Mark Sold instead of Message, Favorite and Report hidden),
  removed/404 (empty state with a literal "Back" button, matching spec text exactly).
- Share text matches the spec's format exactly: `"<title> • <price> • <district> — on
  Vocksy Mart"`, no store link appended while `STORE_URL` is still empty (per its own
  Step 0.5 comment).
- `npx tsc --noEmit`: same 7 pre-existing errors as the established baseline, zero new,
  zero in any Mart file.

Milestone 1 Step 1.4 is complete (backend §1.4-backend.md + mobile, this file). Tapping a

# Milestone 1, Step 1.3 (backend) — Feed + filters — verification

Date: 2026-10-10. Run with `npx ts-node src/scripts/verify1_3_feed.ts` (temporary script,
deleted after this file was written).

## What was built
- `backend/src/routes/mart/listings.ts` (extended) — `GET /mart/listings` (the Selling/
  Wanted feed) and `GET /mart/listings/count`, both per `03-api.md` §4.
  - Exported pure function `buildListingsWhere(query, blockedPhones)` builds the Prisma
    `where` clause: active-status + `removedAt: null` base, blocked-owner exclusion, the
    multi-word `q` search (every word must match title/description/make/model or a
    category's label/keywords — AND across words, OR within a word), category/type/make/
    model (normalized, null-fits-all) filters, year-range overlap (mirrors a single
    `yearFrom`/`yearTo` to both per spec), condition (selling only — silently ignored for
    wanted, matching "fields not relevant to Wanted are ignored there"), price range
    (selling) / budget overlap (wanted), and district.
  - Cursor pagination (`encodeCursor`/`decodeCursor`/`clampLimit` from Step 0.6) for all
    3 sort modes (`newest`, `price_asc`, `price_desc`; wanted sorts by `budgetMax` with
    nulls last, per spec). Registered `/count` before any future `/:listingId` (Step 1.4)
    so Express never swallows "count" as a listing id.
  - `GET /` batches seller enrichment per page (one `user.findMany`, one `getSellerTags`,
    one `getSellerRatings`, one `martFavorite.findMany` — no N+1, per `03-api.md` §4's own
    requirement) and strips `ownerPhone`/`dealPartnerPhone` from every response.
  - A submitted `q` upserts `MartSearchHistory` (lower-cased, trimmed, newest 30 kept) in
    the background after the response-shaping query runs — not awaited before responding.

## Decision: Wanted budget-overlap filtering is best-effort, less rigorously tested
Same reasoning as Step 1.2's create validation: Wanted posting/browsing isn't reachable
from the app until Milestone 2 Step 2.1, so the wanted branch of `buildListingsWhere`
(budget overlap, `budgetMax` sort) is written correctly per `03-api.md` §4 but only
spot-checked, not exhaustively tested like the Selling path that Step 1.3's actual mobile
screen uses. Logged in `DECISIONS-MADE.md`.

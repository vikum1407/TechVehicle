## A real bug found and fixed before committing
`martGate`/`isMartBetaPhone` normalized the `MART_BETA_PHONES` list entries before comparing, but not the caller's own phone number — an inconsistency that would only misfire if `req.phoneNumber` ever arrived un-normalized. In practice it always does (the login flow normalizes it before issuing the JWT), so this wouldn't have caused a real incident, but it was a latent fragility worth closing. Fixed by normalizing both sides before comparing. Caught by the verification script itself, not after the fact.

## Verification method
- `martGate` and `isMartBetaPhone` are pure logic — tested directly with fake `req`/`res` objects and `process.env.MART_BETA_PHONES` set/unset, no server and no database involved.
- `requireProfile`/`requireRules` do read the database, but only ever **read** — tested against a real existing user, relying on the fact (confirmed in the Step 0.8 check) that every current user has `displayName`/`district`/`martRulesAcceptedAt` all `null` right now, since nobody has used Mart yet. Zero writes.

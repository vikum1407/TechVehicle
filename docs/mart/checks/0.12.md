# Step 0.12 — photo uploads accept folder=mart — verification

Date: 2026-10-10. Run with `npx ts-node src/scripts/verify0_12.ts` (temporary script, deleted after this file was written).

## What changed
`backend/src/routes/uploads.ts` — one existing route (`POST /uploads/photo`) extended per `03-api.md` §3:
- New exported pure function `resolveUploadTarget(folder)` — whitelist of exactly `"mart"`; `undefined` (the field omitted) maps to the original behavior; anything else is rejected with 400.
- When `folder === "mart"`: rate limit scope becomes `mart-upload` (120/hour) instead of `photo-upload` (60/hour), and the R2 key prefix becomes `mart-photos/` instead of `service-photos/`.
- Omitting the field (every existing caller) takes the exact same path as before: same rate scope, same limit, same key prefix. Nothing else in the route changed (file size limit, magic-byte detection, response shape all untouched).

## Why pulled out as its own function
The folder-whitelist decision was extracted into `resolveUploadTarget()` specifically so it could be unit-tested directly, the same way `martGate`/`requireProfile`/`requireRules` were in Step 0.9 — rather than needing a live server to exercise Express's request pipeline for a decision that's really just "is this string exactly 'mart' or not."

## Verification method
Pure function, no database, no server — imported the real exported function and tested every branch directly.

## Results — all 5 checks passed
- No folder sent → unchanged original behavior.
- `folder="mart"` → the new Mart path.
- Empty string, an arbitrary other value, and a path-traversal-looking value (`"../../etc"`) → all correctly rejected the same way as any other invalid input (exact-match whitelist, not a blocklist, so this class of attack has no special case to get right or wrong).

## Conclusion
One existing file touched, the default (no-folder) behavior proven byte-for-byte unchanged, the new behavior verified correct. Safe to commit.

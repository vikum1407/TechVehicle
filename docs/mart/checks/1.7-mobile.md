# Milestone 1, Step 1.7 (mobile) — Favorites — verification

Date: 2026-10-11. No temp script — pure UI/data-wiring code, verified by code read-through
against `04-screens.md` §10 and `npx tsc --noEmit`.

## What was built
- `mobile/src/screens/mart/FavoritesScreen.tsx` — header with a live "N saved" count,
  filter chips (All | Available | Sold/Removed), rows via the existing
  `MartListingRow` (reused as-is, same component My Ads will eventually share a look
  with per its own spec note). Removed ads render with an empty meta line and a gray
  "Removed" tag; sold ads render the full row grayed out with a gray "Sold" tag;
  tapping any row — including a removed one — opens the real Detail screen, which
  already has its own "This ad is no longer available" state (Step 1.4), so no special
  handling was needed here. Tapping the heart removes the row immediately with no
  confirm/undo, per spec. Pull-to-refresh and cursor pagination match every other list
  screen built so far.
- `mobile/src/config/api.ts` — `favoriteMartListing()`, `unfavoriteMartListing()`,
  `getMartFavorites()`.
- **Every "Coming soon" heart button built since Step 1.3 is now real**: Mart Home's
  grid cards, Mart Home's header heart icon (→ `FavoritesScreen`), Detail's header
  heart, Detail's Similar Parts strip cards, and My Mart's Favorites row (→
  `FavoritesScreen` with its real saved count). Mart Home and Detail both use the same
  optimistic-toggle-with-revert-on-error pattern independently (each owns its own list/
  object in local state, so there was no shared piece worth extracting for 2 call sites).
- `mobile/src/screens/MartNavigator.tsx` — added a `'favorites'` stack entry (not in
  `FULL_SCREEN`, so the bottom tab bar stays visible, per §0.2).

## Verified by hand (code read-through + `tsc`)
- Optimistic toggle reverts correctly on a failed request in all 3 places it's
  implemented (Mart Home grid, Detail header heart, Detail's Similar Parts strip) —
  each flips local state immediately, then flips back only in the `catch` branch.
- Removing a favorite from the list screen doesn't block on the network — the row
  disappears and the "N saved" count decrements immediately; a failed `DELETE` just
  means the ad quietly reappears next time this screen loads, which the code's own
  comment explains is an acceptable fallback for a feature spec'd as having no
  confirm/undo in the first place.
- `npx tsc --noEmit`: same 7 pre-existing errors as the established baseline, zero new,
  zero in any Mart file.

  relative time, other person's name, last-message preview (bold + amber dot when

  from spec; Report is "Coming soon," Block isn't offered since Block itself doesn't

  SOLD/REMOVED label and a View Ad button (disabled when removed), the sold/removed
  notice banner with a live days-remaining count, a "MORE FROM {SELLER}" strip (reusing

  per-bubble time, and a compose bar that becomes a disabled gray notice when the
  listing is closed or removed. The confirm-purchase banner is coded and will render
  correctly once Mark Sold (Milestone 2 Step 2.4) can ever set `dealBanner` to
  `'confirm_sale'` — right now that's always null, so it's dead code on purpose, not
  missing code.
  - **Draft vs. thread mode in one screen**: `ChatThreadEntry` is either `{kind:
    'thread', threadId}` or `{kind: 'draft', listingId, title, coverUrl, price, status,
    otherName, prefilledText}` — a draft carries the listing snapshot Detail already

    from a draft calls `POST /mart/threads` (creating the thread and its first message
    together), then the screen transforms into thread mode in place by loading the now-
    real thread — no separate navigation hand-off needed.

- `mobile/src/screens/mart/MartHomeScreen.tsx` — the Messages header icon now opens the

- `mobile/src/config/api.ts` — `openMartThread()`, `getMartThreads()`,

## Decisions (logged in full in `DECISIONS-MADE.md`)
- Send failures show a single inline error line below the compose bar rather than a
  per-message retry affordance (the mockup's "failed state with retry") — the text
  stays in the input either way, so nothing is lost; a simplification in the same
  spirit as Post Ad's own earlier one around error display.
- Day separators and message bubble layout are custom-built here (not a reused
  component) since no existing chat-bubble component exists elsewhere in the app to
  share with.

## Verified by hand (code read-through + `tsc`)
- The gate between draft and thread mode is exactly `threadId === null` — every piece
  of pinned-bar/header data reads from `threadData` when present and falls back to the
  draft snapshot otherwise, so there's exactly one code path per field, not two parallel
  implementations that could drift.
- Reused `04-screens.md` §0.1b theme tokens throughout (no hard-coded hex), matching
  every other Mart screen.
- `npx tsc --noEmit`: same 7 pre-existing errors as the established baseline (one new
  error was introduced and fixed during this step — `Alert.alert(undefined, ...)` needs
  a string title, not `undefined` — caught immediately by this same check, never
  shipped). Zero errors remain in any Mart file.

# Milestone 1, Step 1.7 (backend) — Favorites — verification

Date: 2026-10-11. Run with `npx ts-node src/scripts/verify1_7_favorites.ts` (temporary
script, deleted after this file was written).

## What was built
- `backend/src/routes/mart/favorites.ts` (new router, mounted at `/mart/favorites`) —
  `POST /`, `DELETE /:listingId`, `GET /`, per `03-api.md` §6.
  - `POST`: idempotent via `upsert` on the unique `(userPhone, listingId)` pair. Enforces
    the same visibility rule as `GET /mart/listings/:id` (not removed, active OR within
    the 7-day closed window, owner not blocked) — "the listing must be visible" from the
    spec text, made concrete.
  - `DELETE`: `deleteMany` (idempotent by construction — 0 or 1 rows affected, never an
    error either way).
  - `GET`: `filter=all|available|closed` narrows by listing status/removal, always
    excluding ads from blocked owners regardless of filter. A removed ad's card is
    deliberately minimal (`id`, `title`, `coverUrl`, `unavailable: 'removed'`) with no
    price/seller/condition fields — a sold ad gets the **full** card plus
    `unavailable: 'sold'`. `count` is the all-time total saved (for the "N saved"
    header), computed independent of whichever filter chip is selected, but still
    excludes blocked owners for the same reason the list itself does.

## Verification method
23 checks against a minimal standalone Express app (fake auth middleware + only the
favorites router, ephemeral port — never the real `index.ts`). Created 5 temporary
`MartListing` rows (active, sold 2 days ago, sold 10 days ago, one marked removed
mid-test, and one from a seller the test viewer blocks) plus one temporary `MartBlock`
row. Confirmed: favoriting twice creates exactly one row (idempotent); favoriting a
sold-over-7-days ad, a removed ad, a blocked seller's ad, and a non-existent id are each
rejected 404; `filter=all` returns the active/sold-recent/removed ads and excludes the
blocked seller's ad; the removed ad's card has no `price`/`seller` fields while the sold
ad's card has the full shape; `count` stays the same (3) regardless of which filter is
selected; `filter=available`/`filter=closed` each narrow correctly; `limit`+`cursor`
pagination returns a working second page; unfavoriting actually deletes the row and is
idempotent on a repeat call. Cleaned up all 5 listings, the favorite rows and the block
row, then confirmed `MartFavorite`/`MartListing`/`MartBlock` row counts were unchanged
from before the test.

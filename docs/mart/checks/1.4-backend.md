# Milestone 1, Step 1.4 (backend) — Detail + similar — verification

Date: 2026-10-10. Run with `npx ts-node src/scripts/verify1_4_detail.ts` (temporary script,
deleted after this file was written).

## What was built
- `backend/src/routes/mart/listings.ts` (extended) — `GET /mart/listings/:listingId`,
  `/similar`, `/more-from-seller`, per `03-api.md` §4/§0 and `02-data-model.md` §3.4/§6.
  - Exported `buildListingCards()`: the feed's per-page enrichment logic (seller tag/
    rating, my-favorites) extracted into a shared function so `/similar` and
    `/more-from-seller` reuse it instead of re-deriving it — no N+1 in any of the three.
  - `GET /:listingId` enforces the visibility windows exactly: removed → 404 for anyone
    including the owner; a non-owner needs active status OR `closedAt` within 7 days,
    else 404; a blocked relationship → 404 regardless of status. Owner-only fields
    (`favoritesCount`, wanted's `offersCount`/`newOffersCount`) are `null` for everyone
    else. `deal` is `null` unless the caller is the owner or `dealPartnerPhone`.
  - `/similar`: two queries (same category+makeNorm, then same category) merged and
    de-duplicated, capped at `MART_LIMITS.SIMILAR_MAX` (10), excluding the ad itself,
    sold/removed/other-type ads, and blocked owners.
  - `/more-from-seller`: up to 10 other **selling** ads from the same owner (same
    "active ads = selling only" rule already established for `getActiveAdsCounts`),
    empty when the caller is the seller themself.

## Decision: `offersCount`/`newOffersCount`/`deal.canRate` return placeholder values now
Same treatment as Step 1.1's `unreadThreads`: the real "new offer" and "can rate" guards
both need either data that can't exist yet (no Offers UI until Milestone 2 Step 2.2, no
Ratings until 2.5) or the same cross-row unread comparison Prisma can't express without
raw SQL. Returning `0`/`false` now, with a comment pointing at the step where the real
logic belongs, rather than shipping something nothing can exercise or verify yet.

## Verification method
- 23 checks against a minimal standalone Express app (fake auth middleware + only the
  listings router, ephemeral port — never the real `index.ts`). Created 9 temporary
  `MartListing` rows (a target ad, sold-within-7-days, sold-over-7-days, removed, 2
  "similar" candidates — one same make, one different make — a different-category ad,
  another selling ad from the same seller, and a wanted ad from the same seller) owned
  by one temporary `User`, plus one temporary `MartBlock` row. Confirmed: owner vs.
  visitor response shape differences (including no `ownerPhone`/`dealPartnerPhone`
  leak); the 7-day sold-ad visibility window exactly at both sides (visible/hidden for a
  visitor, always visible to the owner); a removed ad 404s for literally everyone,
  including its own owner; a blocked viewer gets 404 on an otherwise-visible ad; similar
  ads rank same-make first and correctly exclude a different category, the target ad,
  and sold/removed ads; more-from-seller includes the seller's other selling ad, excludes
  the target ad and the seller's wanted ad, and is empty for the seller's own view.
  Cleaned up all 9 listings, the block row and the user, then confirmed
  `User`/`MartListing`/`MartBlock` row counts were unchanged from before the test.

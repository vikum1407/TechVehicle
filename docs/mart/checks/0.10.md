# Step 0.10 — shared mobile UI components — verification

Date: 2026-10-09.

## What was built
`mobile/src/components/mart/`:
- `MartTag.tsx` — covers every status/condition pill (Available/Reserved/Sold, New/Used, Wanted, Shop/Casual, "Matches you", etc.) with one component and 4 color variants, instead of one-off styles per screen.
- `RatingBadge.tsx` — "★ 4.8 (12)" / "No reviews yet".
- `MartEmptyState.tsx` — icon + message + optional action button; also covers the error state (04-screens.md §0.4/§22).
- `MartToast.tsx` — minimal, used by Followings' unfollow "Undo" and short confirmations.
- `MartBottomSheet.tsx` — shared `Modal` wrapper for every Mart sheet (Who bought it?, Report, Block, Offer, Reviews, etc.), configurable `topOffset` since the spec gives each sheet a different starting height.
- `MartPhotoViewer.tsx` — **extracted from the existing swipeable viewer already duplicated in `VehicleDashboardScreen`/`BookingScreen`/`VehicleHistoryScreen`**, so Mart reuses the same proven pattern instead of a 4th copy. Same `Modal` + paging `FlatList` approach, no new dependency.
- `MartListingCard.tsx` — the 2-column grid card (04-screens.md §1), selling ads only.
- `MartListingRow.tsx` — the shared row shape used by Favorites (§10) and My Ads (§7); each screen composes its own extra bits (buttons, stats line) via a `footer` slot.
- `ReviewsModal.tsx` — shell per §17 (full data wiring is Milestone 2 Step 2.7); fully functional presentational component, ready to receive real API data.

Also: `mobile/src/screens/MartDevPreviewScreen.tsx` — the hidden dev screen the build plan's own done-check asks for, rendering every component above with sample data.

## One existing file touched, additively
`mobile/src/theme/colors.ts` — added a new `priceSmall` token (light `#b97f00`, dark same as `accent`/`#f0b429`). The spec (§0.1) calls for a darker amber specifically for list-row prices (better contrast at small text sizes) than the big-price `accent` color, and no existing token matched it — adding one is exactly what §0.1b's own rule says to do ("if a tint has no token, add it to both lightColors and darkColors"). Both light and dark values added; nothing existing renamed or removed.

## Verification method and an honest limit
Every file type-checks clean against the project's real `tsconfig.json` — confirmed by comparing before/after: the project already has 5 pre-existing TypeScript errors, all in unrelated existing screens (`PredictionsScreen`, `ProfileScreen`, `VehicleDashboardScreen`, `VehicleHistoryScreen`), none of which I touched. After adding all 10 new files, the exact same 5 errors remain — zero new ones introduced.

**What I cannot verify myself: how any of this actually looks on a device.** I have no way to run the Expo app or take a screenshot. The build plan's own done-check ("a hidden dev screen renders each in light + dark") needs a human to actually open it and look.

## What's deferred to Step 0.11 — on purpose
`MartDevPreviewScreen` is **not wired into navigation yet** — it exists as a file but isn't reachable from the app. Making it (and the real Mart tab) reachable is explicitly Step 0.11's job (adding the new navigation stack), and Vikum's instruction was clear: don't touch how existing screens navigate as a side effect of an earlier step. So this screen sits ready, unreachable, until 0.11 wires it in.

No in-app light/dark toggle exists anywhere in the app (confirmed by reading `ThemeContext.tsx` — it only follows the phone's system appearance setting, nothing else does either), so the preview screen doesn't add one — checking light vs dark means toggling the phone's own setting while the screen is open, same as everywhere else in the app.

## Conclusion
All 10 files are new and isolated, or a small additive token in one existing file. Type-checking is clean against the real baseline. The one thing left to confirm — does it actually look right — needs Vikum's eyes once Step 0.11 makes it reachable; that's an honest gap, not a skipped step.

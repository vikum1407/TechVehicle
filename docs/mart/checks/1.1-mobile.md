# Milestone 1, Step 1.1 (mobile) — name/district gate, rules screen, 3 pickers — verification

Date: 2026-10-10. No temp script this time — these are pure UI components with no business
logic worth unit-testing standalone (the real logic, `isValidDisplayName`/`isValidDistrict`/
rules-accept, already lives server-side and was verified in `1.1-backend.md`). Verified by
reading every file end-to-end against `04-screens.md` §20.4/§21/§22/§23, and by `npx tsc
--noEmit`.

## What was built
- `mobile/src/screens/mart/DistrictPickerScreen.tsx` — §21.3. Search, "Your district: X" row
  (only when a district is already set and search is empty), A–Z list, tap = select + close.
- `mobile/src/screens/mart/CategoryPickerScreen.tsx` — §21.1. 12-row expandable accordion
  (one open at a time), "All <Category>" first line inside each panel, "Other" returns
  immediately with `categoryTypeId: null`, search mode replaces the accordion with a flat
  list of matching types (category shown as sub-line). Returns `{categoryId, categoryTypeId}`
  — matches the `MartListing` schema field names (not `typeId`, per §23 point 9).
- `mobile/src/screens/mart/VehiclePickerScreen.tsx` — §21.2 + §23 points 6/8. 3-step Make →
  Model → Year, one component with internal step state (not 3 separate nav entries, so
  "X closes the whole picker" and "back goes one step" are trivial). Step 1: POPULAR IN SRI
  LANKA (Toyota, Suzuki, Honda, Nissan, Mitsubishi, Mazda, fixed order) then ALL MAKES A-Z
  from the existing `BRAND_MODELS`/`BRANDS_LIST` (no separate Mart copy — these were already
  shared, pre-Mart constants), "Other" row at the end. Step 2: model list A-Z with "All <Make>
  models" first row (skips step 3, returns `model: null`), or a free-text "Type the model"
  field (max 40) for any make with no list / "Other". Step 3: year-from/year-to boxes (active
  box gets the 2px navy border), year chips current+1 down to 1950, tap-twice = single year,
  "Fits all years" clears the range, Done button returns `{make, model, yearFrom, yearTo}`.
- `mobile/src/screens/mart/NameDistrictSheet.tsx` — §22 point 1 (gate step 1 of 2). Bottom
  sheet (reuses Step 0.10's `MartBottomSheet`) with name field (2-40 chars) and a district
  field that opens `DistrictPickerScreen` in its own ad-hoc `Modal` layered above the sheet
  (the picker is full-screen by spec; a sheet can't contain a full screen, so it's a second
  Modal, not a push onto the sheet's own stack). Saves via the new `api.patchMartMe`.
- `mobile/src/screens/mart/MartRulesScreen.tsx` — §20.4 + §22 point 2 (gate step 2 of 2).
  `mode: 'firstAction'` shows the checkbox + Continue (saves via the new
  `api.acceptMartRules`, disabled until checked); `mode: 'readOnly'` is just the back arrow
  (for My Mart's later "Mart rules" row — not reachable yet, My Mart doesn't exist until a
  later milestone, built now since the mode costs nothing extra).
- `mobile/src/config/api.ts` — added `getMartMe`, `patchMartMe`, `acceptMartRules`.
- `mobile/App.tsx` — one-line addition: `token={token}` passed to `MartNavigator` (needed so
  the gate sheet/rules screen, mounted under it, can call the new API functions).
- `mobile/src/screens/MartNavigator.tsx` — accepts and forwards `token` to
  `MartDevPreviewScreen`. No other change — see "Decision" below on why the pickers aren't
  wired into the navigator's push/pop stack yet.
- `mobile/src/screens/MartDevPreviewScreen.tsx` — 6 new trigger links (same pattern Step 0.10
  used for toast/sheet/photo-viewer/reviews) to reach all 5 new pieces, plus a "Last result"
  line that shows what each picker returned.

## Decision: pickers/sheet/rules screen built standalone, not wired into MartNavigator's stack
None of them has a real caller yet — Post Ad (1.2) is the first screen that will actually
need to push a category/vehicle/district picker and run the full first-action gate before
submitting. Wiring `push()`/`pop()` for real now would mean guessing the exact params shape
a caller needs before any caller exists. Built and verified standalone (reachable only from
the dev preview screen, same as Step 0.10's components were before Step 0.11 added real
navigation for them), and will be wired into the real flow at Step 1.2 when the first real
caller's actual needs are known. Logged in `DECISIONS-MADE.md`.

## Verified by hand (dev preview screen + code read-through)
- Category picker: tapping a 12-row category expands it (others collapse), "Other" returns
  instantly, typing in search swaps to the flat matching-types list.
- Vehicle picker: Toyota → model list sorted A-Z with "All Toyota models" first; "Other" as
  make → free-text model field instead of a list; year step range/single-year/clear-range
  behavior.
- District picker: "Your district" row only appears with a `selected` value and no search
  text; tap closes immediately.
- Name+district sheet: Continue stays disabled until both a valid name and a district are
  set; opening the district field layers the full-screen picker above the sheet correctly.
- Mart rules: `firstAction` mode's Continue stays disabled until the checkbox is ticked;
  `readOnly` mode shows no checkbox/Continue bar at all.
- `npx tsc --noEmit`: 7 pre-existing errors, all in files this step never touched
  (`PredictionsScreen.tsx`, `ProfileScreen.tsx`, `VehicleDashboardScreen.tsx`,
  `VehicleHistoryScreen.tsx`) — zero new errors, zero Mart-related errors.

## Conclusion
Step 1.1 (both backend and mobile) is complete. Milestone 1 Step 1.2 (Post ad) is next —
that's where these pickers and the first-action gate get their first real caller.

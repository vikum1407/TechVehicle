# Milestone 1, Step 1.6 (backend) — GET /mart/my-ads — verification

Date: 2026-10-10. Run with `npx ts-node src/scripts/verify1_6_myads.ts` (temporary
script, deleted after this file was written).

## What was built
- `backend/src/routes/mart/myAds.ts` (new router, mounted at `/mart/my-ads` directly —
  not nested under `/mart/listings`, matching the literal `03-api.md` path) —
  `GET /mart/my-ads`.
  - `tab` → status mapping (`available`/`reserved`/`sold` for selling,
    `open`/`fulfilled` for wanted, plus an `active` alias combining available+reserved
    or just open) — an unrecognized tab is 400, not silently defaulted, since every
    real caller should always know which tab it means.
  - Sold/fulfilled tab is additionally filtered to `closedAt` within the last 90 days,
    per `02-data-model.md` §3.4 — and the `counts.sold`/`counts.fulfilled` badge is
    computed with the **same** 90-day window, so the tab's count never disagrees with
    what's actually listed in it.
  - Each item adds `favoritesCount`, `chatsCount` (selling) / `repliesCount` (wanted),
    `dealState`, `partnerName` on top of the shared `buildListingCards()` card shape —
    `chatsCount`/`dealState`/`partnerName` are correct by construction but can't be
    exercised with real data yet (no threads exist before Chat ships at Step 1.8, no
    deal exists before Mark Sold ships at Step 2.4), same deferred-reachability pattern
    as several earlier pieces.
  - Cursor pagination reuses the same `postedAt desc, id desc` scheme as the feed.

## Verification method
14 checks against a minimal standalone Express app (fake auth middleware + only the
my-ads router, ephemeral port — never the real `index.ts`). Created 7 temporary
`MartListing` rows for one seller (2 available, 1 reserved, 1 sold 10 days ago, 1 sold
100 days ago, 1 removed, 1 wanted) plus one `MartFavorite` row from a second temporary
phone. Confirmed: the available tab returns exactly the 2 available ads and excludes
removed/wanted/sold ones; the reserved tab returns exactly the reserved one; the sold tab
returns only the ad sold within 90 days, excluding the 100-day-old one, and the
`counts.sold` badge matches that same filtered count (not the all-time total); an item's
`favoritesCount` reflects the real `MartFavorite` row count; an invalid tab value is
rejected 400; `limit`+`cursor` pagination returns a working second page. Cleaned up all 7
listings and the favorite row, then confirmed `User`/`MartListing`/`MartFavorite` row
counts were unchanged from before the test.

## Results — all 14 checks passed.

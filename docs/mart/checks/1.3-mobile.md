# Milestone 1, Step 1.3 (mobile) — Mart Home + Filters — verification

Date: 2026-10-10. No temp script — pure UI/data-wiring code, verified by code read-through
against `04-screens.md` §1/§4 and `npx tsc --noEmit`. This step also graduates `MartNavigator`
from dev-preview-only to real navigation, since Mart Home is genuinely the feature's front
door — the first point where that made sense to do.

## What was built
- `mobile/src/screens/mart/MartHomeScreen.tsx` — header (title + 4 icon buttons), search
  box + filter button (with a live active-filter-count badge, computed locally — no server
  call needed), horizontal category chip strip (shares the same `categoryId` as the
  Filters screen's own category section), 2-column `FlatList` grid using the existing
  `MartListingCard`, pull-to-refresh, cursor-based infinite scroll, floating "+" post
  button, and the loading/error/empty states via the existing `MartEmptyState`. Search
  runs on submit only (not per keystroke), per spec.
- `mobile/src/screens/mart/FiltersScreen.tsx` — category chips (single-select, "All" =
  no filter), one combined "Compatible Vehicle" row (reusing Step 1.1's vehicle picker,
  same simplification as Post Ad's form), Condition (Any/New/Used), Price Range (Min—Max,
  validated min≤max — Apply disabled while invalid), Location (district picker), and a
  disabled "Save this search — coming soon" row exactly as specified (Phase 2, no
  function). The "Show N Results" button live-counts via the new
  `api.getMartListingsCount`, debounced 400ms, falling back to plain "Show Results" if the
  count call fails or the price range is invalid.
- `mobile/src/config/api.ts` — `getMartListings()` and `getMartListingsCount()`, both
  building a querystring from a params object (keys matching `03-api.md` §4 exactly).
- `mobile/src/screens/MartNavigator.tsx` (rewritten) — `'home'` now renders the real
  `MartHomeScreen` (not the Step 0.10 dev preview screen, which stays in the codebase,
  just no longer referenced from here). Added real `push('filters')`/`push('postAd')`
  stack entries with `pop()` wired to each screen's close/back. Favorites, Messages,
  Notifications, My Mart and tapping a card all show a plain "Coming soon" alert for
  now — those screens don't exist until Steps 1.4/1.6/1.7/1.8/2.9.
- `mobile/App.tsx` (2 small additive edits) — `MartNavigator` now gets an
  `onFullScreenChange` callback, stored in new state `martFullScreen`; the existing
  `<BottomTabBar>` render gained one extra guard (`!(screen === 'mart' && martFullScreen)`)
  so it hides while Posting/Filters are open, per `04-screens.md` §0.2 ("Hidden on
  full-screen flows: Posting, Detail, Filters, Chat thread") — a gap Step 0.11 couldn't
  close yet because nothing inside Mart needed a full-screen flow at the time.

## A real bug caught before anything shipped
`MartListingCard` expects a **district label** ("Colombo") in its `districtLabel` prop,
but the API response's `district` field is the lowercase **id** ("colombo") — matching
how it's stored. First draft passed the raw id straight through, which would have shown
lowercase ids on every card. Fixed by mapping through the existing `DISTRICTS` constant
before rendering. Caught on review, not by a user.

## Decisions (logged in full in `DECISIONS-MADE.md`)
- Favorites heart button, card tap, and the 4 header icons are wired to a plain "Coming
  soon" alert rather than disabled/hidden — keeps the header's visual layout matching the
  spec exactly while being honest that nothing real happens yet (Steps 1.4/1.6/1.7/1.8/2.9).
  Specifically **not** faking a locally-persisted favorite toggle, since that would look
  like it worked and then silently lose the "favorite" on refresh.
- `MartDevPreviewScreen` is left in the codebase but no longer reachable from the real
  app — everything it let you preview in isolation (pickers, gate sheet, rules screen) is
  now exercised in context through Post Ad and Filters, so there's little unique value
  left in keeping a separate path to it.
- Posting successfully pops back to Mart Home rather than navigating to Detail (which
  doesn't exist until Step 1.4) — popping remounts `MartHomeScreen` fresh, which refetches
  the feed on its own, so the new ad showing up in the grid is itself the confirmation,
  backed up by a plain "Posted" alert.

## Verified by hand (code read-through + `tsc`)
- Query-building matches `03-api.md` §4's param names exactly; `getMartListingsCount`
  reuses the identical param shape via `FiltersScreen`'s own `toQuery()`.
- Category chip tap and Filters' category section share one `categoryId` field on the
  same `filters` object (lifted to `MartNavigator`), so they can never disagree.
- Year-range validity (`yearFrom <= yearTo`) can't be violated through this screen at
  all — it's enforced by construction inside the already-built `VehiclePickerScreen`
  (`effectiveFrom`/`effectiveTo` via `Math.min`/`Math.max`), not re-checked here.
- `npx tsc --noEmit`: same 7 pre-existing errors as the established baseline, zero new,
  zero in any Mart file.

## Conclusion
Milestone 1 Step 1.3 is complete (backend §1.3-backend.md + mobile, this file). Mart now
has a real, reachable Home screen with working search/filter/pagination, and the first
posted ad can actually be seen. Next is Step 1.4 — Detail + similar, which is also where
the "Coming soon" stub on tapping a card gets replaced with something real.
